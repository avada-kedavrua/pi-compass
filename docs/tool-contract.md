# Compass tool contract — current development source

Seven fixed tools are registered for the session; nothing is loaded, opened or hidden by Compass. `compass_state` is the only read surface. Agent payloads are selected JSON, never merged internal receipts: `content[0]` is the Agent-facing object, native `details` carries protocol state. A mutation receipt returns only the next cursor plus what the next step needs. Validation failures state that nothing changed. Raw Pi history, native tool identity and the Human's tool preferences remain native-owned.

## compass_goal — semantic definitions only

`set` in main drafts the Agent's interpretation: `current`, the complete `constraints` list and an optional complete `criteria` list. No source refs are required. The Human confirms this definition separately from the plan. Omission of `criteria` preserves the current definitions; `[]` clears them. Criterion IDs (`AC1…`) are assigned by code and returned once. `decide` records a material decision (`summary`, optional `rationale`/`evidence`/`supersedes`/`taskIds`). `checkpoint` records a real recoverable `ref`.

`update` changes the existing Goal without resending definitions. In `constraintEdits` or `criterionEdits`, send `{text}` to add, `{id,text}` to change, or `{id}` to remove. Read IDs from `view:"goal"`; changed definitions get new IDs, so stale evidence cannot target new criteria. Reference canonical repository rules rather than copying their text. Omit edits to reaffirm unchanged definitions after reviewing new Human input.

A different `current` replaces the Goal: version increments, the plan resets, criteria restart, unresolved native runs block replacement. Within the same objective, editing final criteria invalidates the corresponding acceptance evidence and Goal approval, not the DAG approval. Update any task whose work or acceptance changes. New Human input pauses execution until reviewed; reviewing unchanged definitions does not invalidate their stamps.

Only `compass_goal` defines criteria. Plan and acceptance use the Goal's criteria; neither keeps a second editable criterion list.

## compass_state — all reads

Views: `summary` (default, compact), `goal`, `plan`, `acceptance`, `history`, `execution`, `retained`. Summary returns `cursor`, `frame`, Goal, outcome, latest-input ref, plan progress, acceptance counts and a bounded event delta; an exact repeat of the same cursor returns `{unchanged:true,cursor}`. `delta.historyGap`/`cursorAhead`/`omitted` mark bounded history instead of claiming completeness. Cursors are opaque and apply only to `summary`; do not construct or decode them.

`goal` returns criterion IDs/text, Human answers (when the native record exists), decisions, checkpoints and the latest-input review state. `plan` returns tasks and the same progression fields as plan receipts: `prompt` and `next` for an unsent proposal, `goalApproval` and `approval` for the independent stamps, `ready.parent` for automatic frame admission and `ready.code` for manual Code Mode work, `dispatchEligible` for automatic candidates (not running), `assess` for completed prerequisites that need review, `waiting` for frame/input blockers, and `dispatchIssue` for a shared native dispatch blocker when applicable. `execution` returns unresolved batches and the most recent terminal batch, with exact per-attempt IDs and evidence. `retained` lists current-frame and inherited memory/Skill refs. `acceptance` returns criterion status/evidence and `independentlyVerified:false`.

## compass_plan — optional DAG

`define` replaces the full graph (2–24 tasks). `patch` accepts partial `upsertTasks` keyed by task ID and `removeTasks`, returning the material task diff and a warning for an edgeless graph. Each task names `executor: parent|code|subagent`; a `subagent` task must use `writeScope:"read-only"` and a `dispatchReason` of at least 12 characters explaining why a separate semantic context is worth the call. Goal criteria must exist first. Definition is a draft: it never authorizes execution or gates Goal completion. `discard` removes an inactive plan and revokes its proposal/approval without changing Goal acceptance or native history; active frames and running or unknown attempts must settle first.

From main, `request_approval` reuses usable proposals and renews only outstanding stamps. When both stamps are valid, Compass opens the first eligible `parent` node in approved list order at Pi’s next completed turn boundary. `return(outcome)` settles the node and opens an eligible successor before the next request without a main turn. `code` work uses `start` and `done`; `subagent` work uses correlated native dispatch/results only. `reopen` resets a terminal task and affected dependents, never an active dependent. `assess` records a semantic check (`pass|fail|inconclusive` + evidence, caveats and unresolved caveats) and requires current Human approval. `resolve` reconciles only the exact current `unknown` batch and requires `confirmedNoActiveRuns:true`, concrete `confirmationEvidence` from native status, and one terminal result per unresolved attempt in that batch. Already recorded terminal results must not be resubmitted.

`throw` reports why active work invalidates the plan, with evidence and optional known `sideEffects` (omitting them means unknown). A delegated task uses the same outcome in its structured result. A stopped DAG cannot start new work or fall back, but still accepts correlated terminal results. The first correlated child `throw` wakes idle main or steers the active frame via Pi. It does not forcibly close a frame or cancel siblings. Inspect `compass_state(view:plan)` for the stop and revise the plan before seeking approval. `cancel` takes a `taskId` and exact unresolved `requestId` from `compass_state(view:execution)`; request it only for a sibling whose work is invalidated. It does not confirm termination or undo changes.

**Approval transport.** Forward the latest `prompt` unchanged to `ask_user_question` from main once the definitions are ready. Compass expands it to one native tab per pending definition. Each approval requires its exact preview echo, question index, native call identity and current definition. A clean tab can be approved independently in a partial submission; unanswered or note-qualified tabs do not approve, and a global note holds both. TUI only: RPC, print and unavailable UI fail closed.

**Execution.** After exact approval, Compass uses the registered pi-subagents package’s public launch preflight for each primary or fallback attempt. An unavailable shared bridge/preflight leaves native tasks pending with a visible reason. A refused node profile blocks that node before launch; independent eligible nodes can still run and no native attempt is created for the refusal. Fix the profile and `reopen` the blocked node. Use a configured read-only profile; `writeScope` and budgets are not enforcement. The preflight is a launch snapshot, not an OS sandbox or an atomic pin of files that change before native launch. Compass consumes only valid correlated terminal results and retains unknown correlations for a bounded interval. It never force-enables or rewrites native tool activation. Code and parent tasks are never delegated. A missing start acknowledgement or terminal response, a session shutdown or a branch change leaves the batch `unknown`; nothing is retried automatically and no task is presumed started. Dependent tasks unlock only when their dependency chain has current passing assessments, without an unrelated sibling barrier. Changing a prerequisite assessment invalidates downstream assessments, not execution evidence. Unknown attempts pause new native dispatch; valid late evidence rechecks eligibility under the current approval and Human input. Child success is evidence, not Goal acceptance.

## compass_acceptance — evidence only

`{results:[{criterion,status,evidence}]}` records `reported_pass|failed|blocked|inconclusive` for existing current criterion IDs. Unknown or duplicate criteria fail before mutation; an identical repeat is a no-op. This is an Agent report, never independent verification; the deterministic outcome projection classifies recorded evidence, it does not prove correctness.

## compass_context — memory, frames, values

Flat actions (`pin`, `unpin`, `remember`, `call`, `return`, `load`, `replace`, `drop`, `mark`, `move`, `spill`, `transfer`). All refs are opaque; copy them unchanged. One `pin`/`unpin`/`remember` may accompany sibling tools; every other operation must be a standalone call. A `queued` result is provisional: only the correlated native applied/rejected receipt becomes active, so never poll or blindly retry.

`pin` retains complete original content; a verified complete native `SKILL.md` read auto-pins in its current frame. `remember` stores Agent-authored compact memory with optional sources and caveats. List it with `compass_state(view:"retained")`; `replace` and `drop` edit or remove local Agent-authored memory directly. `unpin` releases retention without deleting raw history. In a child it masks inherited retention for descendants, not for the parent. Lifetime defaults to the current Goal, or session before a Goal exists; explicit `lifetime:"goal"` requires a Goal.

A frame is same-session attention, not a second Agent, transcript store or filesystem rollback. `call` creates a local scope with explicit `capture` (`ref` borrows read-only, `copy` is private and editable; its receipt returns the refs in capture order). `return` exports only `exportSources`/`result`: explicitly exported retained values keep their declared lifetime in the parent, ordinary working exports do not become retained, and unexported local work releases.

For a node frame, `return` accepts one outcome: `done` attests node acceptance with evidence and optional caveats, `blocked` needs a reason, and `throw` needs both reason and evidence plus optional known side effects. A reported pass is not independent verification. Plan state advances only after the frame change commits. `fromTasks` declares artifact dependencies between parent nodes; use `dependsOn` for order without imports. A passing producer assessment is not enough if an export is missing or stale: the consumer is not ready. When startable, Compass imports the exact exported refs and caveats. `inputRefs` reuses explicitly selected exact exports from earlier work. These inputs are currently supported for parent nodes. Ordinary frames still use `task` and have no plan outcome.

Successful exact repeats of a compatible native read keep the latest payload at the tail and put a pointer in the previous projected tool result. The raw exchange is unchanged. Failed, changed, protected and merely similar evidence is not auto-deduplicated.

`load` makes an exact copy; `replace`/`drop` edit or drop eligible working values; `mark` records handling; `move` verifies a complete repeated read against `verifiedAgainst`; `spill` writes and readbacks a new project-relative artifact before emitting its pointer. After `replace`/`spill` or a remainder-changing `move`, use the updated ref from the applied receipt. A frame cannot return with live owned watches: unwatch or `transfer` them first.

`compass_context` is a direct model tool, not a nested Code Mode tool. If a Code Mode script fails after an earlier Compass mutation succeeded, that earlier call stays committed; check its receipt and settle the task instead of replaying the batch.

Context schema v6 is current-only. Older snapshots fail visibly; there is no migration, argument adapter or silent reset. Filesystem and environment effects are never rolled back.

## runtime_guard — executable mechanical checks

`runtime_guard({operation:{action,...}})`: `get|put|test|remove` manage Agent-written pure-JS checks under session/local/global scope revisions with CAS. `put` validates code and optional cases before activation and does not echo code. Default scope is session; local binds the canonical project cwd; global affects the profile store. Local cannot weaken global.

Coverage is the native `tool_call` observation, including Code Mode nested calls — not later plugin rewrites, independent child processes or arbitrary OS actions. `warn` leaves business results untouched and delivers boundary feedback to the parent; `block` prevents the observed call and returns a native error. `unknown` stays unknown, the control tool stays repairable, and no rule is generated from Human prose. See [runtime-guards-design.md](runtime-guards-design.md).

## Boundaries

`parent` and `code` execution stay with the main Agent; only exactly approved, ready, read-only `subagent` tasks are dispatched. Task completion, assessment, independent review and Goal acceptance remain distinct. Local tests prove local behavior only: they do not establish live Pi/provider quality, cache effects or lower total cost.
