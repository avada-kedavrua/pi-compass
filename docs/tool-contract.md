# Compass tool contract — current development source

Compass tool content is Agent-facing JSON, selected explicitly rather than merged from private metadata. Goal/plan mutations return `resultStatus: applied|unchanged` and the minimum next-action state. Context receipts expose only commitment status, newly created source refs and meaningful frame/results. Reads return domain data directly; there is no generic success/kind boilerplate or repeated prose summary. Context operations return queued first, then a correlated native applied/rejected receipt. Expected validation errors explain what did not change. Native `details` carries protocol state, not an accidental second Agent payload. Full caveats/evidence are retained in their on-demand reads. Mutation names are not repeated in payloads; the native tool call already supplies operation identity. Source identity is one opaque `ref`; native bindings, hashes, revisions and full lineage stay behind the consumer projection. Triage records return applied/unchanged plus the new cursor, since recording a review changes Compass bookkeeping. A matching native tool-result is never removed to save bytes; complete call/result pairing remains mandatory. Automatic dispatch feedback is a field in the same owned JSON receipt, not appended prose that breaks programmatic decoding.

The tool surface is progressive. `compass_state` is the compact default read; use other tools only when current work needs them. The Agent chooses decomposition, attention and route; code validates deterministic state and safety boundaries. A frame or DAG is optional. Task completion and Agent-reported acceptance are not independent Goal verification.

## Goal state and work plans

- `compass_goal` explicitly records the Agent’s semantic objective, complete constraint list and optional acceptance criteria. `expectedVersion=0` creates the first Goal. `sources` is an explicit list of original Human refs from state/search/details. It must cover the actual objective/constraints; it does not default to the latest message. Latest-input review is a separate native identity, so a follow-up does not replace semantic provenance. Runtime validates identity/version, not the meaning of the interpretation. Raw prose never creates, changes or approves a Goal.
- Reaffirm the same objective and constraints after new Human input before resuming approved DAG progression. This preserves existing Human approval if the material definition is unchanged. Different objective text replaces Current Goal, increments its version and resets Goal-specific work; unresolved native run identities block replacement. Original Goal is the initial semantic interpretation, with original Human source references, not a duplicate transcript or Goal-change archive.
- `compass_state` returns a compact Goal/outcome/frame summary and only meaningful plan/acceptance information. It omits native inventory, repeated Goal events and empty diagnostics. Native tool diagnostics remain in `/compass-preflight`; Goal sources, constraints and answers are on demand in `compass_goal_read`; both reads expose reusable `input.ref` when relevant; `reviewed` is meaningful only once a Goal exists. `reviewed=false` means the Agent has not reviewed that input, not that runtime has detected which constraint is semantically wrong or obsolete.
- Cursors include Goal revision, event sequence and native context revision (`R…-E…-C…`). Pass a previous cursor for bounded event deltas; omissions and retained-history gaps are explicit. Treat cursors as opaque and copy unchanged. Exact unchanged reads return only cursor/unchanged; changed reads expose `frame:"root"` or the current frame identity, not three empty frame fields. `compass_history_recent` and `compass_triage` provide on-demand event evidence.
- `compass_open` offers optional groups; `context` is also available without a Goal, while Goal-specific groups require one; the Agent chooses which to load. No Goal wording or write-count heuristic chooses planning or creates a DAG.
- `compass_plan_create` is optional. Tasks explicitly select `parent`, `code` or `subagent`; only read-only Subagent tasks can be auto-dispatched. `dispatchReason` must justify the extra semantic call. Code and parent tasks are not silently delegated.
- `compass_plan_status` reads readiness and stable task IDs. `compass_plan_revise` checks the current state version and unresolved execution state. `compass_task(action=...)` validates task identities, dependencies and lifecycle preconditions. Subagent tasks are started by Compass after eligible plan/task mutation boundaries; do not start them manually.
- `compass_execution(action=status|resolve)` is for failed or unresolved native batches. An unknown child must first be checked through native pi-subagents status; never infer it stopped or retry it automatically.

**Approval and progression contract:** A DAG is a draft until a correlated structured Human answer approves the exact Goal/criteria/tasks/dependencies/executors/constraints binding. Declined, partial, modified, stale and UI-error answers do not approve. Plan revision/constraint changes invalidate approval; task progression and auto-dispatch remain blocked until current approval. A completed task requires a separate explicit `assess` result with evidence; dependencies unlock only after a passing assessment with no unresolved caveats. Task completion, assessment, independent review and final Goal acceptance remain distinct. These code paths have local regression coverage; tests do not establish real Human UI or provider behavior.

## Runtime guards

`runtime_guard({operation:{action,...}})` is available independently of Goal/capability loading. `get|put|test|remove` manage Agent-written pure JS checks under session/local/global scope revisions. A put validates code and optional cases before CAS activation; no full definition echo. Get defaults to compact metadata; scoped filters have distinct cursors. Global/local share a profile SQLite store; session definitions use native branch entries.

The Human-approved guarantee is the native tool_call observation point (direct and nested), not final post-plugin parameters or independent children. Warn does not edit business results; native boundary notices reach the parent even when nested results are discarded. Block prevents the observed action and preserves a short error exchange. Failed checks stay unknown, control operations remain repairable, and no rule is auto-generated from Human prose. See the [execution contract, budgets and example](runtime-guards-design.md).

## Context: find, remember, then optionally edit

The common path has no frame or revision lookup prerequisite:

1. compass_context_search({query}) finds missing evidence and returns short excerpts plus reusable source refs.
2. remember({text,sources,caveats?}) stores an Agent-written compact conclusion with those refs/caveats. Pin is different: it retains complete original content, so use it only when the full body must remain visible.
3. Read compass_context_search({refs,view:"handles"|"details"}) when an exact ref is needed again. Do not combine query with refs. Known refs resolve before limiting, across all available scopes unless sourceScope restricts them.

All mutation examples are operations inside compass_context({operation:{action,...}}), not separate tools. The basic schema contains only pin, unpin and remember. view=handles omits text; view=details adds read qualifications, content-relative ranges and reusable provenance refs. Ordinary results omit request echoes, empty/default audit fields and repeated native identity tuples. Nonempty caveats remain authoritative qualifications. Excerpts do not claim complete source bodies; bounded result sets report incomplete.

Refs are opaque selections of exact data, not names for a working set. Copy them unchanged. Code validates native identity, binding, content version and branch, captures the current revision internally, and checks again at commit. A stale mutation never silently selects newer content. Pure recovery/load may explicitly select an older available version; that is not a new observation. Source ranges refer to recovered content, not absolute file line numbers; read.fileRange is separate.

Context mutations remain model-only direct standalone calls because of the native validated-boundary contract; they cannot be nested or parallel with other tools. queued is provisional. The boundary emits applied/rejected without requiring polling, and only committed state becomes active. Protocol correlation and revisions remain in native metadata. Filesystem/environment effects are not rolled back.

### Optional context capability

Open compass_open({capabilities:["context"]}) once for call/return, load/replace/drop/mark, move/spill and watch transfer. The schema is not expanded merely because a task status changes.

- call has a local task and explicit capture; default none. ref shares the outer value, copy creates a private value. Its applied receipt returns sources in capture order: edit private copies through those new refs, not original source refs. The task remains visible inside the frame.
- return exports only exportSources/result; other local process is released. Writes through shared refs survive. Native external/Human facts and complete exchanges remain protected. The Human footer shows depth/identity; Agent state uses the same frame identity as search.
- load makes an exact data copy; replace/drop edit only eligible projection values, not raw history. Code supplies protocol companions and their preconditions; Agent does not manually gather call/result versions. Mutations that change a value return its updated ref; use that for later edits, export or artifact recovery instead of searching/reconstructing a version. mark manages handling; retirement releases retention, not raw evidence.
- pin can explicitly retain the exact successful complete native Skill-file read with skill=true. Loaded/private/derived data cannot be promoted to that original activation. Retention defaults to Goal or, before one exists, session; explicit Goal lifetime requires a Goal for both pin and remember.
- move(verifiedAgainst=ref) verifies a complete repeated read internally. Source path/range/payload identity is required; subsets also require a shared native file revision. Later conflicting or incomplete reads reject the operation. Pinned companions cannot be consumed, and similarity never proves sameness. No separate comparison/ranking ritual or background optimizer is added.
- spill writes/readbacks a new project-relative artifact before emitting its pointer. Linux descriptor-relative traversal protects the reviewed race; other platforms fail closed. A rejected later commit can leave a reported artifact; recovery verifies its receipt rather than silently falling back.
- A frame cannot return with live owned watches. Native pi-await owns arm identity/liveness; unwatch or transfer to target=parent/root first. Repeating wakes stay live.

Parent restoration uses native references under a 2 MiB control budget, not copied parent bodies. Operations remain linear in active sources and may affect cache prefixes. Stock Pi request overlays can recover omitted pins and materialize some snapshots at existing boundaries; immediate post-compaction canonical restoration and provider cache benefits are not guaranteed. Context schema v5 is current-only: old rendered v4 snapshots fail visibly; no migration, old public argument adapter or silent reset is provided. Raw Pi history remains unchanged.

## RouteSet

The optional routes capability exposes a persisted RouteSet separate from the DAG. Alternatives are not DAG siblings and are not automatically fanned out. Initial route choice uses the exact structured Human questionnaire, correlated through the persisted exchange, or an acceptance-gated result from already authorized exploration. `propose_exploration` prepares a new scope/budget/routes proposal; only its clear native Human answer authorizes it. Model-visible input cannot supply fabricated questionnaire results. Notes, partial/declined answers and UI errors withhold authorization. RouteSets contain 2–3 alternatives so their native questionnaire has at most four options. Competitor cancellation is exact-identity and acceptance-gated, with request/acknowledgement/terminal/unknown tracked separately. The RouteSet does not create branches or worktrees; filesystem/worktree coordination remains the Agent's responsibility. A selected route binds the DAG approval to its exact baseline/route; route changes invalidate prior task evidence and require fresh approval before execution.

Mutation receipts do not echo the whole RouteSet, submitted criterion bodies or an old questionnaire. They return current stateVersion/selection/winner and the affected run identity/status/gate, including unresolved criterion IDs and material caveats. Only create/propose returns the generated questionnaire. `status` remains the on-demand full evidence read.

## Native Subagents and waits

Compass delegates eligible read-only child tasks through the documented pi-subagents Structured Delegation API. It does not force-enable native tools or alter the user's tool preferences. pi-subagents owns child execution/status/cancellation; pi-await owns watch lifecycle/wakes. Compass correlates receipts and consumes child feedback but does not claim child success as Goal acceptance. Recursive Compass use inside children is not supported by the installed launch contract.

## Acceptance

`compass_acceptance_status`, `compass_acceptance_define` and `compass_acceptance_record` manage Goal criteria separately from DAG task status. Definition receipts return current IDs/statuses; status reads return complete current criterion text/evidence without prose clipping or duplicated summaries. Duplicate/over-limit definitions and over-limit evidence fail before mutation rather than silently truncating. Goal replacement reports reset counts; it never promotes old criterion reports into a new Goal. This does not mandate when the Agent defines or records acceptance. A task marked done or an Agent-reported pass is not independent verification. Missing, stale, partial or contradictory evidence remains unknown/inconclusive.
