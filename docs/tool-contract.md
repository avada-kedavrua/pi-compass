# Compass tool contract — current development source

Seven fixed tools are registered for the session. `compass_state` is the GoalRun read surface. Raw Pi history, native tool identity and the Human's tool preferences remain native-owned.

**Result format follows the consumer.** Use compact JSON in `content[0]` for values the Agent or Code Mode may reuse verbatim: IDs, revisions, refs, cursors, status, and exact next-call arguments. Include a cursor only when the matching view can use it. Use plain text for a short explanation and Markdown bullets for grouped notices without a programmatic consumer. Keep Pi protocol metadata in `details`; do not repeat the same payload as both JSON and prose or modify another tool's result to carry a notice. Failures distinguish no mutation from an uncertain outcome.

## compass_goal — semantic definitions only

`set` in main drafts the Agent's interpretation: `current`, the complete `constraints` list and an optional complete `criteria` list. No source refs are required. The Human confirms this definition separately from the plan. Omission of `criteria` preserves the current definitions; `[]` clears them. Criterion IDs (`AC1…`) are assigned by code and returned once. `decide` records a material decision (`summary`, optional `rationale`/`evidence`/`supersedes`/`taskIds`). `checkpoint` records a real recoverable `ref`.

`update` changes the existing Goal without resending definitions. In `constraintEdits` or `criterionEdits`, send `{text}` to add, `{id,text}` to change, or `{id}` to remove. Read IDs from `view:"goal"`; changed definitions get new IDs, so stale evidence cannot target new criteria. Reference canonical repository rules rather than copying their text. Omit edits to reaffirm unchanged definitions after reviewing new Human input.

A different `current` replaces the Goal: version increments, the plan resets, criteria restart, unresolved native runs block replacement. Within the same objective, editing final criteria invalidates the corresponding acceptance evidence and Goal approval, not the DAG approval. Update any task whose work or acceptance changes. New Human input pauses execution until reviewed; reviewing unchanged definitions does not invalidate their stamps.

Only `compass_goal` defines criteria. Plan and acceptance use the Goal's criteria; neither keeps a second editable criterion list.

## compass_state — all reads

Views: `summary` (default, compact), `goal`, `plan`, `proposal`, `acceptance`, `history`, `execution`, `retained`. Summary returns `cursor`, `frame`, Goal, outcome, latest-input ref, plan progress, acceptance counts and a bounded event delta; an exact repeat of the same cursor returns `{unchanged:true,cursor}`. `delta.historyGap`/`cursorAhead`/`omitted` mark bounded history instead of claiming completeness. Cursors are opaque and apply only to `summary`; do not construct or decode them.

`goal` returns criterion IDs/text, scoped Human answers, decisions and checkpoints. In a frame, neither `summary` nor `goal` advertises already-reviewed parent input; new input remains visible. Recover earlier native messages explicitly with `compass_context_search`.

`plan` returns compact task status and progression. Add `taskId` to read one node’s definition, evidence, artifacts and caveats. Identical completion and assessment evidence is returned only once; assessment history records the event and task ID, not a second copy. `prompt` and `next` guide approval; `goalApproval` and `approval` are independent. `ready.parent` is automatic admission; `ready.code` is manual Code Mode work. `afterFrame` lists graph-ready serial/main work while a frame owns the session, subject to actual input admission at the boundary. `dispatchEligible` lists native candidates, not running tasks. `assess` lists missing prerequisite assessments, `review` lists explicit non-passing assessments, `waiting` explains input blockers, and `dispatchIssue` explains native dispatch blockers. `execution` returns unresolved batches and the most recent terminal batch, with exact per-attempt IDs and evidence. `retained` lists pinned memory/Skill refs, not all context. Use `compass_context_search({view:"cleanup"})` for large removable working groups; each suggested ref represents one whole exchange. Drop only groups no longer needed. `acceptance` returns criterion status/evidence and `independentlyVerified:false`.

## compass_plan — optional DAG

`define` replaces the full graph (2–24 tasks). `patch` accepts partial `upsertTasks` keyed by task ID and `removeTasks`, returning the material task diff and a warning for an edgeless graph. Each task names `executor: parent|code|subagent`; a `subagent` task must use `writeScope:"read-only"` and a `dispatchReason` of at least 12 characters explaining why a separate semantic context is worth the call. Goal criteria must exist first. Definition is a draft: it never authorizes execution or gates Goal completion. `discard` removes an inactive plan and revokes its proposal/approval without changing Goal acceptance or native history; active frames and running or unknown attempts must settle first.

From main, `request_approval` reuses usable proposals and renews only outstanding stamps. When both stamps are valid, Compass opens the first eligible `parent` node in approved list order at Pi’s next completed turn boundary. `return(outcome)` settles the node and opens an eligible successor before the next request without a main turn. `code` work uses `start` and `done`; `subagent` work uses correlated native dispatch/results only. `reopen` resets a terminal task and affected dependents, never an active dependent. `assess` records a semantic check (`pass|fail|inconclusive` + evidence, caveats and unresolved caveats) and requires current Human approval. `inconclusive` is the normal result when the work is complete but semantic coverage is not established; it holds dependents without pretending the task failed. `resolve` reconciles only the exact current `unknown` batch and requires `confirmedNoActiveRuns:true`, concrete `confirmationEvidence` from native status, and one terminal result per unresolved attempt in that batch. Already recorded terminal results must not be resubmitted.

Semantic review is optional and Agent-selected. When the task's risk or uncertainty justifies another model call, define a separate read-only `executor:"subagent"` task with `agent:"reviewer"` or `agent:"evidence-auditor"`, an acceptance condition that asks it to try to falsify the implementation, and a `dispatchReason` that explains the added cost. Feed it only the exact Goal, constraints and evidence it needs. Its result is evidence, not approval; the main Agent records `assess(pass|fail|inconclusive)` and carries caveats into the Goal. Do not add a reviewer for every task and do not encode domain-specific edge cases in Compass.

`throw` reports why active work invalidates the plan, with evidence and optional known `sideEffects` (omitting them means unknown). A delegated task uses the same outcome in its structured result. A stopped DAG cannot start new work or fall back, but still accepts correlated terminal results. The first correlated child `throw` wakes idle main or steers the active frame via Pi. It does not forcibly close a frame or cancel siblings. Inspect `compass_state(view:plan)` for the stop and revise the plan before seeking approval. `cancel` takes a `taskId` and exact unresolved `requestId` from `compass_state(view:execution)`; request it only for a sibling whose work is invalidated. It does not confirm termination or undo changes.

**Approval transport.** From main, call the native `ask_user_question` tool directly with the latest `prompt` unchanged. It is not a Code Mode tool; ordinary chat cannot approve. Missing transport returns activation guidance, not a usable prompt. Compass expands an opaque proposal into one native tab per pending definition. `view:"proposal"` shows the exact pending preview from main only, on demand; it is for inspection, not questionnaire arguments. Each approval requires its exact preview echo, question index, native call identity and current definition. A clean tab can be approved independently in a partial submission; unanswered or note-qualified tabs do not approve, and a global note holds both. TUI only: RPC, print and unavailable UI fail closed.

**Execution.** After exact approval, Compass uses the registered pi-subagents package’s public launch preflight for each primary or fallback attempt. An unavailable shared bridge/preflight leaves native tasks pending with a visible reason. A refused node profile blocks that node before launch; independent eligible nodes can still run and no native attempt is created for the refusal. Fix the profile and `reopen` the blocked node. Use a configured read-only profile; `writeScope` and budgets are not enforcement. The preflight is a launch snapshot, not an OS sandbox or an atomic pin of files that change before native launch. Compass consumes only valid correlated terminal results and retains unknown correlations for a bounded interval. It never force-enables or rewrites native tool activation. Code and parent tasks are never delegated. A missing start acknowledgement or terminal response, a session shutdown or a branch change leaves the batch `unknown`; nothing is retried automatically and no task is presumed started. Dependent tasks unlock only when their dependency chain has current passing assessments, without an unrelated sibling barrier. Changing a prerequisite assessment invalidates downstream assessments, not execution evidence. Unknown attempts pause new native dispatch; valid late evidence rechecks eligibility under the current approval and Human input. Child success is evidence, not Goal acceptance.

## compass_acceptance — evidence only

`{results:[{criterion,status,evidence}]}` records `reported_pass|failed|blocked|inconclusive` for existing current criterion IDs. Unknown or duplicate criteria fail before mutation; an identical repeat is a no-op. The receipt includes the resulting Goal `outcome`: all criteria can be reported as passed while authorized DAG work remains incomplete. This is an Agent report, never independent verification. A test report, node `done`, child success or review result must not be silently upgraded to independent verification.

## compass_context — memory, frames, values

Flat actions (`pin`, `unpin`, `remember`, `call`, `return`, `load`, `replace`, `drop`, `mark`, `move`, `spill`, `transfer`). All refs are opaque; copy them unchanged. One `pin`/`unpin`/`remember` may accompany sibling tools; every other operation must be a standalone call. A short provisional receipt means the projection is unchanged yet. The turn-end receipt reports `applied` or `rejected`; use any returned refs from that receipt, and do not poll or blindly retry.

`pin` retains complete original content; a verified complete native `SKILL.md` read auto-pins in its current frame. `remember` stores Agent-authored compact memory with optional sources and caveats. List it with `compass_state(view:"retained")`; `replace` and `drop` edit or remove local Agent-authored memory directly. `unpin` releases retention without deleting raw history. In a child it masks inherited retention for descendants, not for the parent. Lifetime defaults to the current Goal, or session before a Goal exists; explicit `lifetime:"goal"` requires a Goal.

A frame is same-session attention, not a second Agent, transcript store or filesystem rollback. `call` creates a local scope with explicit `capture` (`ref` borrows read-only, `copy` is private and editable; its receipt returns the refs in capture order). From inside a frame, a distinct nested `call` requires `parentFrame` equal to the active frame ID. `return` closes one level and its receipt gives the remaining depth. It exports only `exportSources`/`result`: explicitly exported retained values keep their declared lifetime in the parent, ordinary working exports do not become retained, and unexported local work releases.

For a node frame, standalone `return` takes `outcome`, not `result`: `done` attests node acceptance; `inconclusive` records completed work without a passing assessment and holds dependents; both need evidence (at most 1,600 characters, with exact citations or selected exports for longer material). `blocked` needs a reason; `throw` needs reason and evidence plus optional known side effects. Review or reopen an inconclusive task from main once there is more evidence. A reported pass is not independent verification. Plan state advances only after the frame change commits. `fromTasks` declares artifact dependencies between parent nodes; use `dependsOn` for order without imports. A passing producer assessment is not enough if an export is missing or stale: the consumer is not ready. When startable, Compass imports the exact exported refs and caveats. `inputRefs` reuses explicitly selected exact exports from earlier work. These inputs are currently supported for parent nodes. Ordinary frames still use `task` and have no plan outcome.

Successful exact repeats of a compatible native read keep the latest payload at the tail and put a pointer in the previous projected tool result. The raw exchange is unchanged. Failed, changed, protected and merely similar evidence is not auto-deduplicated.

`load` makes an exact copy; `replace`/`drop` edit or drop eligible working values; `mark` records handling; `move` verifies a complete repeated read against `verifiedAgainst`; `spill` writes and reads back a new project-relative `.json` artifact under an existing directory before emitting its pointer. After `replace`/`spill` or a remainder-changing `move`, use the updated ref from the applied receipt. A frame cannot return with live owned watches: unwatch or `transfer` them first.

`compass_context` is a direct model tool, not a nested Code Mode tool. If a Code Mode script fails after an earlier Compass mutation succeeded, that earlier call stays committed; check its receipt and settle the task instead of replaying the batch.

Context schema v6 is current-only. Older snapshots fail visibly; there is no migration, argument adapter or silent reset. Filesystem and environment effects are never rolled back.

## runtime_guard — executable mechanical checks

`runtime_guard({operation:{action,...}})`: `get|put|test|remove` manage Agent-written pure-JS checks under session/local/global scope revisions with CAS. `put` validates code and optional cases before activation and does not echo code. Default scope is session; local binds the canonical project cwd; global affects the profile store. Local cannot weaken global. A cursor is only for a repeated listing of the same scope. `put`/`remove` return the committed scope revision, not a listing cursor. `get` with `id` reads the full rule.

Coverage is the native `tool_call` observation, including Code Mode nested calls — not later plugin rewrites, independent child processes or arbitrary OS actions. `warn` leaves business results untouched and delivers a short boundary notice to the parent; `block` prevents the observed call and returns a native error. `unknown` stays unknown, the control tool stays repairable, and no rule is generated from Human prose. See [runtime-guards-design.md](runtime-guards-design.md).

## Boundaries

`parent` and `code` execution stay with the main Agent; only exactly approved, ready, read-only `subagent` tasks are dispatched. Task completion, assessment, independent review and Goal acceptance remain distinct. Local tests prove local behavior only: they do not establish live Pi/provider quality, cache effects or lower total cost.
